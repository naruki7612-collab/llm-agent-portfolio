# 07 — メディア選定エージェント

広告媒体の資料PDF群をデータベース化し、
「金融業界の経営層向けにタイアップで300万以内」のような自然文の要件から
媒体を選定して提案書を生成します。

| ファイル | 内容 |
|---|---|
| [`media_agent.py`](media_agent.py) | 選定エージェント本体（3,774行） |
| [`media_db_builder.py`](media_db_builder.py) | 媒体資料PDF → 50列のマスタDB構築 |
| [`docs/flow.md`](docs/flow.md) | 処理フローの解説 |
| [`docs/system_prompt.md`](docs/system_prompt.md) | システムプロンプト |

## DB構築側（`media_db_builder.py`）

媒体資料のPDFから、料金・リーチ・読者属性・掲載形式など50列を抽出してマスタ化します。
ここで手を抜くと選定側がいくら賢くても当たらないので、工数の大半はこちらに掛かっています。

抽出のコスト目標は**1件あたり20〜30クレジット**に置きました。
資料は数十ページあるものが多く、素朴に全ページを1回の呼び出しに入れると
上限に当たるか、当たらなくても精度が落ちます。

## 選定側（`media_agent.py`）

ターン制です。1ターン目で要件を解釈して候補を出し、
2ターン目以降は状態を引き継いで絞り込みや深掘りを行います。

呼び出し経路が2つあるのが実装上の注意点です。
**メインAIが直接パラメータを渡す経路（本番）** と、
**自然文をLLMが翻訳して渡す経路**で、パラメータの形が変わります。
改修時に片方だけ直して本番で動かない、という事故を起こしたので、
検収は必ず両経路で確認しています。

## 反映経路が分かれている

- `.py` を直した → **RAGに再登録**しないと反映されない
- `.md`（プロンプト）を直した → **テンプレートを貼り直す**必要がある
- 新しいツールを使うようにした → **ツール許可**の設定が要る

コードを直しただけでは動きません。この3つを検収チェックリストにしています。
