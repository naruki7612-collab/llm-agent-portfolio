# 02 — 請求書の自動仕訳パイプライン

PDFの請求書を読み取り、伝票にまとめ、勘定科目を判定して、
会計システムに取り込めるCSVを出すまでを通しで行います。

## 8段構成

| 段 | ファイル | やること |
|---|---|---|
| s10 | [`s10_ingest.py`](pipeline/s10_ingest.py) | PDFの取り込みとページ画像化 |
| s20 | [`s20_extract.py`](pipeline/s20_extract.py) | Vision で明細を構造化抽出 |
| s30 | [`s30_vouchers.py`](pipeline/s30_vouchers.py) | 明細を伝票単位に束ねる（規則ベース） |
| s32 | [`s32_group_llm.py`](pipeline/s32_group_llm.py) | 規則で決まらない束ね方を LLM に委ねる |
| s35 | [`s35_split.py`](pipeline/s35_split.py) | 1伝票が複数科目にまたがる場合の按分 |
| s40 | [`s40_classify.py`](pipeline/s40_classify.py) | 勘定科目・部門・税区分の判定 |
| s50 | [`s50_export.py`](pipeline/s50_export.py) | 取込CSVの生成 |
| s60 | [`s60_feedback.py`](pipeline/s60_feedback.py) | 確定仕訳を突き合わせて辞書を更新 |

[`run_all.py`](pipeline/run_all.py) が通し実行。支援モジュールは
`rules.py`（正規化と判定規則）、`prompts.py`、`store.py`（マスタ参照のキャッシュ）、
`config.py`、`notefs.py`、`pdfimg.py`、`jsonlog.py`、`selftest.py`。

## 途中結果を残す設計

1回の実行に時間上限があるため、未処理PDFを一定本ずつのバッチに割り、
バッチ単位で s20〜s50 を通して結果CSVに追記します。
途中で上限に当たっても、そこまでのバッチは失われません。
再開は結果CSVの「参照元ファイル」列を見て未処理分だけを拾うので、
一時ディレクトリが消えていても続きから進みます。

## 精度の測り方

[`eval/eval_by_line.py`](eval/eval_by_line.py) と
[`eval/eval_by_voucher.py`](eval/eval_by_voucher.py) の2本を用意しています。
前向き検証（学習に使っていない月で計測）の結果は、
**会計上正しい判定 78% / 行単位の完全一致 70%** でした。
粒度で数字が変わるため、片方だけを出すことはしていません。

ボトルネックは科目判定ではなく **s30〜s35 の「行の割り方」** です。
束ね方を間違えると、後段が正しくても伝票単位では不正解になります。

### 評価で踏んだ失敗

プロンプトに評価期間の実例を書いたところ、行単位の一致率が 18pt 上がりました。
プロンプトは LLM 呼び出しのたびに渡されるので、答えを書けばそのまま下駄になります。
実例は学習期間から採り、規則の形に書き換えて載せるようにしています。

### 確信度では足切りできない

モデルの確信度が高いものを自動確定に回す設計を試しましたが、
**自動確定分の 15% が誤り**でした。確信度と正誤が対応していないので、この設計は採っていません。
