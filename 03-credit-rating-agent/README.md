# 03 — 債務者区分判定エージェント

企業の財務指標と外部情報から、与信管理上の債務者区分を判定します。
出力はExcelの所定セルへの差し込みで、**判定根拠を必ず併記**します。

| ファイル | 内容 |
|---|---|
| [`credit_rating_agent.py`](credit_rating_agent.py) | 本体。指標算出 → マトリックス引き当て → 外部情報の収集と判定 → Excel出力 |
| [`docs/system_prompt.md`](docs/system_prompt.md) | 呼び出し側のシステムプロンプト |
| [`tests/verify_cases.py`](tests/verify_cases.py) | 回帰テスト |
| [`tests/gen_fixtures.py`](tests/gen_fixtures.py) | テスト用の入力データ生成 |

## 判定の構造

区分は縦軸（財務内容の段階）と横軸（延滞状況）の**マトリックスの交点**で決まります
（`MATRIX_TABLE`）。交点に特例条件を重ねて最終区分を出し、
縦軸・横軸・交点・特例・最終区分・判定根拠をそれぞれ別セルに書きます。

分解しているのは、間違えたときに**どこで間違えたかが分かる**ようにするためです。
最終区分だけを出力すると、指標の読み違いなのか、マトリックスの引き方なのか、
特例の適用なのかが切り分けられません。

## LLMに任せる範囲

- **任せる**: 非定型の資料からの数値の読み取り、外部情報（業界動向・信用情報）の要約と評価
- **任せない**: 指標の計算、マトリックスの引き当て、特例の適用

計算をコードに寄せているのは、検算できる形にしておくためです。
外部情報の判定でも、`★本文に根拠がなければ推測せず「不明」` をスキーマの説明文に入れて、
埋めさせないようにしています。

## 未解決だったもの

実務で使っている帳票には**延滞月数を記入する欄がありませんでした**。
マトリックスの横軸は延滞状況で決まるため、帳票だけでは横軸のB〜I列に到達できず、
99通りの組み合わせのうち実際に到達できたのは6通りです。
入力経路を別に用意する必要があり、そこは設計として残しています。

また、実質債務償還年数の算式が社内2資料で食い違っており、
どちらを正とするかは審査部門の確認待ちでした。
こういう「仕様が割れている」箇所は勝手に決めず、確認事項として上げています。
