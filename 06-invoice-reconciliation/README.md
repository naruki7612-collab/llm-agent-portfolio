# 06 — 請求書突合

リフォーム工事の請求書PDFから値を抽出し、基幹システムから出した2種類のExcelと
突合して、差分をHTMLレポートにします。

| ファイル | 内容 |
|---|---|
| [`reconcile.py`](reconcile.py) | 抽出と突合の本体 |
| [`report_html.py`](report_html.py) | 突合結果のHTMLレポート生成 |
| [`docs/system_prompt.md`](docs/system_prompt.md) | エージェント側のシステムプロンプト |

## 2フェーズ

```
フェーズ1  請求書PDF → 構造化データ（Vision, schema指定）
フェーズ2  抽出データ ↔ 2つのExcel（テキスト判定, schema指定）
```

抽出と突合でモデルを分けています。画像から読むのと、読んだ結果を突き合わせるのは
別の仕事なので、同じ呼び出しに混ぜると片方の失敗がもう片方を巻き込みます。

## スキーマを3つに分けた

2つのExcelは列構成が違います。そこで、

1. **両方に共通する列**（`COMMON_SCHEMA`）をまず抽出
2. それぞれにしか無い列を**追加抽出**（`RIFORM_ONLY_SCHEMA` / `SHUZEN_ONLY_SCHEMA`）

の順にしています。共通部分を先に確定させると、片方のExcelにしか無い列の抽出が失敗しても
突合の土台は残ります。

## 取りに行かない列を決めておく

請求金額（売価）・請求先名・掛け率・家主／契約者情報・社内進捗管理項目は、
**構造的に請求書からは絶対に取得できない**ことを事前検証で確認しました。
これらはLLMに問い合わせません。

聞けば何かしら答えが返ってきますが、それは推測です。
取れないと分かっている列を空のまま残すほうが、突合結果として正しくなります。

## スクリプトの置き場所

本体は会話やシステムプロンプトに埋め込まず、RAGインデックスに登録して
実行のたびに取り寄せる形にしています。コードが長いのと、
エージェント側を触らずにスクリプトだけ差し替えられるようにするためです。
