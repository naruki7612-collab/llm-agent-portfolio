# 06_財源額集計表

財源額集計表アシスタント（アルファリース・質問対応サポート枠）。
基幹システムから出るリース割賦情報CSVを、お客様の「財源集計表」Excelの
当日列に転記し、前日以下の部店に色を付け、集計サマリとメール本文を返す。

## この帳票の作り

「集計表」シートに**同じ形の表が3つ縦に並ぶ**。

```
行3     A列 = '8月'         ┐
行4     日付ヘッダ            │ 1つ目
行5〜36  16部店 × 2行         ┘   （A～C財源 / D財源）

行38    A列 = '9月'         ┐
行39    日付ヘッダ            │ 2つ目
行40〜71 16部店 × 2行         ┘

行73    A列 = '53期下期'     ┐  ← ラベルは古いまま。実態は「翌々月」
行74    日付ヘッダ            │ 3つ目
行75〜106 16部店 × 2行        ┘
```

**3表は上から 当月 / 翌月 / 翌々月**（8月ファイル = 8月・9月・10月）であり、
**日付列は3表とも共通（＝実行日）**。1回の実行で3表すべての同じ列に、
それぞれの月の集計値が入る。

**ファイルは月ごとに新しく切り替わる**（9月なら 9月・10月・11月／
12月なら 12月・翌1月・翌2月）。先方確定・2026-09-08。

CSVは案件のパイプライン一覧で、各案件に「検収予定月（時期）」が付いている。
だから将来月の見込みが日々変動し、それを追いかけるのがこの帳票の目的。

## 使い方

```bash
python3 make_month_file.py 2026-09   # 9月ファイルの骨組みを作る
python3 test_update_zaigen.py        # 受け入れ検証（無加工の原本で6ケース）
python3 test_marume.py               # 8/8版との丸め挙動の比較
```

`make_month_file.py` が作るのはラベル・日付列・数式の骨組みだけ。
**目標(C列)・月初(E列)・要増加(B列の1つ目の表)は空**にしてある。
経営が決める数字と月初スナップショットなので生成できない。
空のまま実行しても書き込みは動くが、`update_zaigen.py` が名指しで警告を出す。

**目標は前月から引き継がない。** 翌月のうちは据え置きだが「当月になる時点で
改定」されていた（7月版の8月目標 535 → 8月版の8月目標 700）。
古い値が残るのを避けるため空にしている。

## スクリプトが原本を読める仕組み

お客様の原本は「月ラベルが文字列」「日付ヘッダが `=F4` の参照」という作りなので、
構造の読み取りをそれに合わせている。

| 何を | どうやって |
| --- | --- |
| 対象ファイルの判定 | シート「集計表」があり、**E列に「月初」の行がある**か（書式に依存しない） |
| 表の区切り | E列が「月初」の行の1つ上が月ラベル行 |
| 集計対象の月 | **表の位置**で決める（上から 当月／翌月／翌々月）。ラベルは照合にのみ使う |
| 日付ヘッダ | `=F4` のような同一シートの単純参照は**辿って解決**する |
| 色付けの比較相手 | 当日列の左で、**実際に値が入っている最も近い列**（実行が飛んでも機能する） |

**ラベルを集計の根拠にしない。** 原本のラベルは実態と食い違うことがあり、
8月ファイルの3つ目は「翌々月（10月）」なのに `'53期下期'` のまま残っていた。
ラベルから月が読めた場合だけ位置と照合し、食い違えば `[警告]` を出す
（前月のファイルを添付した取り違えを拾える）。

**月として読めないラベルの表は、区切りとしては扱うが書き込まない。**
区切りから外すと直前の表が範囲を広げ、部店名が同じため後勝ちで上書きされ、
別の月のデータを書き込む事故が起きる（実測で再現済み）。

## 安全に止まる条件

書き込み先や集計対象が確定できないときは、途中まで書かずに終了コード1で止まる。

| 条件 | 挙動 |
| --- | --- |
| 当月表のヘッダに実行日の列が無い（休日・前月ファイル） | `ValueError` で停止。日付列を足したりはしない |
| **CSVに当月ぶんの案件が1件も無い** | `ValueError` で停止。**0を1セルも書かない**（2026-09-10 追加） |
| Excelの中身が想定と違う（シート・見出し） | `FileNotFoundError` で停止 |
| 将来月（翌月・翌々月）がCSVに無い | **停止しない**。`[情報]` を出して0を書く（まだ受注が無い月） |

**当月がCSVに無い場合に0を書いてはいけない。** 9月ファイルに8月ぶんだけの
CSVを添付すると、96セルすべてに0が入り「ABC 検収額合計：0 千円」という
メール本文まで出てしまう。これは「財源がゼロ」ではなく「その月のデータが無い」
であり、事実と違う数字が原本に残る。`財源保有状況` シートは以前から
「CSVに無い月の列は触らない」を守っていたので挙動も矛盾していた。

## 確定した運用（2026-09-08）

- **3表は 当月 / 翌月 / 翌々月**。3つ目は下期累計ではない
- **ファイルは月ごとに新しく切り替える**（年跨ぎも同じ）
- **日付を指定して更新する**。毎営業日連続で実行される前提ではないので、
  色付けの比較相手は「直近で値が入っている列」にしている（2026-09-10）
- 月次ファイルの骨組みは `make_month_file.py` で作れる。ただし
  **誰が用意するのかは未確認**（先方側の想定）

## 未確定の運用（先方確認待ち）

- **AB/AC/AD列（要増加比・月初比・前日比）は当日列に追随しない。**
  3表とも「最後に値が入った列」を指しており、手でずらしている形跡がある
- **返却された更新版を次回の入力にする運用が回っていない**（8/21・8/25とも
  まっさらな原本が添付されていた）

## 環境メモ

ローカルの Python は 3.9 でスクリプトの `int | None`（3.10+）が通らないため、
テストは `from __future__ import annotations` を挿入したコピーを実行する
（挿入位置は docstring 終端を探して決める。行番号を決め打ちしない）。
**この挿入はテスト時だけで、`update_zaigen.py` 本体には入れていない。**
実行環境 側は 3.11+ なので素のまま動く。
