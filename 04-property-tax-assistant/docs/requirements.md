## 業務の中身

ALI保有不動産の納税管理。毎年4月ごろ各自治体から「固定資産税・都市計画税 納税通知書」が届く。
同封の**課税明細書**にある物件ごとの
- 評価額
- 固定資産税 課税標準額
- 都市計画税 課税標準額

を、Excelの**自治体名シート**の**該当物件の行**へ転記する（現在は手作業。Excel内「マニュアル」シートに手順あり）。
転記が済むとシート内の数式が税額・小計を自動計算し、「納付スケジュール」シートの支払管理につながる。

対象Excelは3ファイル構成（自治体名ごとのシート）:
1. `28期_固都税・償却資産税（①福岡県).xlsx`
2. ②九州_福岡県以外
3. ③九州以外

## 何が壊れているか（担当Aさん調査済み）

お客様自作アシスタントの出力を検査した結果:
- 書き込まれたのは「福岡市博多区」シートの**5セルのみ**、**5セルとも誤り**
- 内訳: 見出し2セル + 小計のSUM数式3セル を、**数値の文字列で上書き**
- 本来の転記先である物件の行には**1セルも書かれていない**
- 原因: **Excelの実構造が仕様に反映されていない**

## 要件（確定事項）

- 入力: 納税通知書PDF + 対象Excel。**実行のたびにルームへ添付される前提**
- 突合キー: **所在地番の一致**
- 書き込みは**数値として**（文字列で入れない）
- 納税通知書は1自治体で複数通の束。博多区は「単独名義／共有名義／償却資産」の3通。
  → **単独名義と共有名義の両方が転記対象**
- **対象外**: 償却資産の納税通知書 / シート内「納付書③」（償却資産）以下の行（お客様が別資料から入力する運用）
- **変更禁止**: 見出し・数式・書式・他シート
- **fail closed**: 地番が突き合わせられない明細、判読できない値 → 書かずに報告して停止
- **検算**: 転記後、シートの小計（SUM数式）＝ 納税通知書表紙の合計額 で照合（読み取りミスの機械的検出）
- **学習データ**: 現行は自治体別PDF 11本が学習データに入っているが、これらは「実行時の入力」なので
  修正版では**学習データから外す**。学習データはプログラム等の毎回変わらないものだけにする
  （どの実行がどのファイルを処理したか特定できるようにするため）。11本は他自治体の様式サンプルとして開発時参考に使う

## 受け入れ

福岡市博多区の実物一式で実行し、担当Aさん用意の**期待値表**（課税明細書から独立に転記した表）と**全セル照合**。
細部は着手時に受領。

## 期日と進め方

- 希望期日: 2026-08-19（水）／理想は 2026-08-21（金）のクライアント定例までに博多区分が動くこと
- ただし**先に期日を約束しない**方針。まず1日作業して「読み取りの手応えと完了見込み」を報告する
- 想定リスク: PDFはスキャン画像でテキスト層はOCR文字化けが多い。課税明細書の数十行×3値は**画像としての読み取り**になる。
  ここが安定するかで「数日で済む／方式の再検討が要る」が分かれる
- 読み取りが安定しない場合の進め方（対象の絞り込み、人の確認を挟む方式）は担当Aさん側で再検討

## 技術メモ（実行サンドボックス、着手前調査）

- `code_execute` サンドボックスのプリインストール: pdfplumber / pypdf / PyPDF2 / openpyxl / pillow / opencv-python / pandas
  （**pypdfium2・poppler・PyMuPDF は無い** → PDF→画像のラスタライズが要るなら `pdf` skill を load する。同skillが pypdfium2 を vendoring）
- `llm_call` は `file_paths=` でPDFを document ブロックとして渡せる。ただし **PDFは Gemini系モデルでしか処理できない**
  （非Geminiを指定すると `gemini/gemini-3.1-flash-lite` に自動フォールバック）
- 添付サイズ上限: Gemini + PDF の組み合わせは **32MB**（PDF無しなら64MB）
- 実行環境利用可能モデル: gpt-5.4-nano/mini, gpt-5.5, claude-haiku-4-5, sonnet-4-6, sonnet-5, opus-4-7,
  gemini-3.1-pro-preview, gemini-3-flash-preview, gemini-3.1-flash-lite, gemini-3.5-flash
  → スキャンPDFの明細読み取りは **gemini-3.1-pro-preview** が第一候補
- `code_execute` の実行窓は約300秒。複数PDF/ページは `asyncio.gather` で並列化必須（Semaphore 6程度）
- 既存の house pattern として `skills/xlsx`（非構造→構造化xlsx、A0設計→A1ルーティング→A2知覚→A3突合→A4組み立て）が
  ほぼこの案件の形。ただし本件は「新規xlsx作成」ではなく**既存xlsxの該当セルへの上書き**なので A4 は openpyxl での
  ピンポイント書き込み（数式・書式を壊さない）に置き換える
